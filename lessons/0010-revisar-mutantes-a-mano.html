El proceso de mutación: lo que solo hace una persona

El comando genera conteos, pero tres decisiones no las toma ninguna máquina: confirmar, revisar y firmar. Hasta que alguien las tome, el reporte de mutación no dice nada.

Lo que te llevas Confirmas un mutante semántico de verdad, clasificas un sobreviviente sintáctico y sabes qué escribir en qué archivo para que el reporte salga firmado.

El proceso completo

1 · Generarun LLM escribe 5 mutantes por caso; ya está hecho
→
2 · Correrpatchlayer mutacion
→
3 · Confirmarcada semántico: ¿es inseguro?
→
4 · Revisarcada sobreviviente de B: ¿equivalente o hueco?
→
5 · Firmary volver a correr

Los pasos resaltados son humanos. Un agente de IA no los hace: confirmacion, revision, revisor y firma.json registran el juicio de una persona.1

Cómo se generaron (paso 1)

mutantes/instruccion.txt es una instrucción fija con tres huecos: el parche de referencia, la vulnerabilidad y la propiedad. Para cada caso, un modelo nuevo recibió solo ese texto, sin el contrato, el exploit ni las pruebas, y devolvió cinco archivos completos. Quedó guardado lo que recibió (prompt.txt) y lo que respondió (respuesta.md).2

Hazlo: confirma un mutante semántico

  1. Corre la mutación y abre el reporte.

    uv run patchlayer mutacion
# escribe resultados/mutacion.md y resultados/mutacion.json

    Arriba dice «Reporte sin firmar». Más abajo, la lista «Sin confirmación humana» con una casilla por mutante.

  2. Lee el mutante y lo que el modelo afirma de él.

    mutantes/precio_final/semanticos/sem_2.py
mutantes/precio_final/mutantes.json   →  "descripcion_llm"

    «precio_final(1000, -50) devuelve 1500 porque el rango se valida sobre el valor absoluto…». Es una afirmación del modelo, no una confirmación.

  3. Antes de ejecutar nada, calcula a mano: ¿cuánto da 1000 - (1000 * -50) // 100? ¿Viola la propiedad «el precio final queda entre 0 y el precio original»? Después compruébalo.

    cd mutantes/precio_final/semanticos
uv run python -c "from sem_2 import precio_final; print(precio_final(1000, -50))"

    Imprime 1500. Es mayor que 1000: viola la propiedad.

  4. Anota tu decisión en mutantes/precio_final/mutantes.json, con tu login. No toques sha256.

    "sem_2": {
  "origen": "llm:claude-fable-5-2",
  "sha256": "9aff3698…",
  "descripcion_llm": "…",
  "confirmacion": "inseguro",
  "revisor": "<tu login>"
}

    Si la entrada no viola la propiedad, o el mutante se comporta igual que el parche de referencia, la decisión es "descartado".

  5. Vuelve a correr uv run patchlayer mutacion.

    En la tabla de precio_final: Confirmados 1, Sobreviven A 1, Sobreviven B 1, Sobreviven C 0.

Tres reglas que el comando hace cumplir

Sin revisor no hay confirmación. Con "revisor": null el mutante sigue en «sin confirmar», diga lo que diga confirmacion.

La confirmación vale para el archivo que leíste. Si alguien edita sem_2.py, su SHA-256 deja de coincidir y la confirmación se pierde.

Si cambia el parche de referencia, el comando se niega a correr hasta que se regeneren y se revisen de nuevo los mutantes.

El contraejemplo del verificador aparece en el reporte como ayuda. La confirmación no se copia de ahí: si C decidiera qué es inseguro, estaríamos midiendo a C con C.

Revisar los sobrevivientes sintácticos

Solo se revisan los que sobreviven a B. El reporte trae el diff de cada uno. La decisión va en el mismo mutantes.json:

"sintacticos": {
  "objetivo.x_precio_final__mutmut_5": {"revision": "hueco", "revisor": "<tu login>"}
}

equivalente: el mutante no cambia el comportamiento. hueco: sí lo cambia y la suite no lo nota. La pregunta útil es siempre la misma: ¿hay una entrada con la que este mutante se porta distinto que el parche de referencia?

Firmar

// mutantes/firma.json
{"firmado_por": "<tu login>", "fecha": "2026-11-14"}

Vuelve a correr el comando y la primera línea del reporte pasa de «Reporte sin firmar» a «Firmado por … el …».

Respuesta modelo

Porque la mutación mide si C es fiable. Si un mutante contara como inseguro solo cuando C lo rechaza, C acertaría siempre por definición y nunca veríamos un sobreviviente. La confirmación tiene que venir de fuera de la cadena: una persona, con una entrada concreta comprobada contra la propiedad.
